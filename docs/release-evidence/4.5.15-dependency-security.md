## FFmpeg and CVE-2026-8461

The official v4.5.15 image reports FFmpeg 8.1.2 and libvips 8.17.3. The Paon
candidate is Debian 13.6 and reports FFmpeg/ffprobe
`7:7.1.5-0+deb13u1` and libvips `8.16.1-1+deb13u1`; `ldd` resolves
`libvips.so.42` for `/usr/local/bin/paon`. Paon reports version 7.3.0.

The lower-looking FFmpeg version is a Debian security backport, not the
vulnerable upstream 7.1.5 build. Debian marks trixie's
`7:7.1.5-0+deb13u1` fixed for
[CVE-2026-8461](https://security-tracker.debian.org/tracker/CVE-2026-8461)
through [DSA-6361-1](https://security-tracker.debian.org/tracker/DSA-6361-1),
and the exact-image Trivy report contains 0 rows for that CVE.

Paon additionally applies `-protocol_whitelist file,pipe,fd,crypto,data` to
every media input. In the exact image, a crafted local HLS playlist whose
segment was `http://127.0.0.1:9/segment.ts` was rejected by both FFmpeg and
ffprobe with `Protocol 'http' not on whitelist`. The control whitelist
`file,http,tcp` attempted `tcp://127.0.0.1:9` and reached connection refusal,
proving the fixture contained a real nested network reference.

## Process-role smoke

Smoke used isolated PostgreSQL 14 and Redis 7 containers with synthetic
credentials. Fresh-schema `paon-migrate` and `paon --check-config` passed. The
first role smoke exposed an unconditional admin-metric query of the removed
`imports` table; that gap was fixed and covered by a fresh PostgreSQL 14 test
before the final image was built.

The exact final image then produced these results:

- `worker`: Docker healthy, worker ready file present, Asynq started, and no
  listener on port 3000;
- `all`: Docker healthy, `/health/ready` and
  `/api/v1/streaming/health` returned `OK`, and logs contained no application
  errors or obsolete `imports` query;
- authenticated SSE on port 3000 returned the initial `:)` event and performed
  a controlled disconnect; authenticated WebSocket opened on the same port and
  then performed its controlled close; and
- the exact-image `--check-config` container exited 0.

The source-frozen role sequence also exercised `web` without a worker ready
file, graceful worker shutdown/readiness cleanup and restart, and a real Asynq
unknown-task fixture with `max_retry=0`. That task moved from pending to archived
with `retried=0/max_retry=0`, while the worker logged `asynq_task_failed` and
`Retry exhausted`. Production rolling restart, failover, and queue recovery
under load remain separate admission gates.

## Reproduction commands

The principal commands were:

```bash
rtk env TMPDIR="$PWD/.go-tmp" GOTMPDIR="$PWD/.go-tmp" \
  GOCACHE="$PWD/.go-buildcache" GOMODCACHE="$PWD/.go-modcache" \
  go mod tidy -diff

  GOCACHE="$PWD/.go-buildcache" GOMODCACHE="$PWD/.go-modcache" \
  go run golang.org/x/vuln/cmd/govulncheck@latest -show verbose ./...

rtk env TMPDIR="$PWD/.release-cache/tmp" docker build --pull \
  --build-arg SOURCE_COMMIT=ce8586c293a0e2474e98521e70cd9e58576dfec5 \
  --tag paon:4.5.15-compat-final .
rtk docker save --output .release-cache/paon-4.5.15-compat-final.tar \
  paon:4.5.15-compat-final
rtk docker run --rm --network none --user 1000:1000 \
  --volume "$PWD/.release-cache/paon-4.5.15-compat-final.tar:/audit/image.tar:ro" \
  --volume "$PWD/.release-cache/trivy-cache:/cache" \
  aquasec/trivy:latest image --input /audit/image.tar --cache-dir /cache \
  --skip-db-update --scanners vuln --severity HIGH,CRITICAL \
  --ignore-unfixed --exit-code 1 --no-progress
```

The ignored `.release-cache/` currently retains the tar, Trivy JSON/database,
and synthetic smoke fixtures for review and is not a release artifact. No real
credentials, tokens, request bodies, application data, or external destination
were captured.

## Release disposition

The exact candidate has clean reachable-Go, frontend high/critical,
CVE-2026-8461, nested-media-network, and fixable-container high/critical gates.
Its worker/all process-role smoke also passes. Production admission is still
pending explicit review of the one moderate frontend build-chain finding, the
non-reachable but fixable NTLM dependency, and the 211 unfixed Debian
high/critical rows. It also requires the live federation/browser/migration and
production-topology gates listed in `4.5.15-compatibility.md`. Rebuild and
repeat these checks if the application tree, dependency lock, base image, or
promoted immutable image changes.
