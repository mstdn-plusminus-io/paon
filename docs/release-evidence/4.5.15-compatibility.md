## Official Quote runtime boundary

Mastodon 4.5 makes Quote authoring and outgoing federation part of the official
contract. Paon therefore uses the official PostgreSQL `quotes` model, REST
entities and actions, FEP-044f activities, notifications, streaming, search,
and retained-design composer as its only live Quote implementation.

The former Paon DynamoDB Quote extension is offline during normal operation.
Its only supported use is the existing resumable, read-only-input,
one-way `paon-admin quotes cutover` into the official PostgreSQL model. The web,
worker, REST, serializer, ActivityPub, streaming, search, and composer paths do
not fall back to DynamoDB, write new DynamoDB Quote state, or dual-write. Any
eventual DynamoDB retirement is a separate explicit operator action.

## Production admission still required

This checkout has automated compatibility evidence, but it is **not declared
production ready**. The following gates remain pending and require a live
reference, production-like infrastructure, or human evidence:

- run public, authenticated, owner, and admin response differentials against a
  live official Mastodon 4.5.15 Rails deployment;
- exercise official Quote/FEP-044f, FEP-7888, numeric actor identifiers, RFC
  9421 and legacy signatures, reply fetching, follower synchronization, and
  lifecycle edge cases with live remote Mastodon and other federated servers;
- complete desktop/mobile/touch/keyboard/screen-reader/reduced-motion testing
  and retained-theme visual regression in real browsers, including the Quote
  composer, nested status states, reply refresh, feeds, settings, and admin
  flows;
- rehearse the staged migration and rollback on production-volume data,
  measuring locks, table rewrites, replica lag, disk headroom, backup/restore,
  old/new writer fences, and the destructive-contract acknowledgement;
- rehearse the deployed PostgreSQL/Redis topology, Redis or compatible-service
  failover, web/worker rolling restart, storage and Meilisearch failures, mail,
  FASP, media processing, and queue recovery under production-like load; and
- complete the explicit dependency/image risk disposition and rebuild/rescan if
  the promoted image, base packages, dependency lock, or application tree
  changes.

Production admission is a separate decision after these items are evidenced;
the `7.3.0` / `4.5.15` / API `7` identity does not waive them.
