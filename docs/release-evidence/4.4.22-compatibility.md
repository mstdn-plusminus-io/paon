## Official quote compatibility boundary

Mastodon 4.4 verifies and displays received remote FEP-044f quotes, but does not
yet let users quote other posts. Paon therefore accepts and displays official
incoming quote state and authorization while rejecting `QuoteRequest` and
omitting quote-create REST, scheduled-status, composer, and outbound
ActivityPub fields. The removed Paon composer controls are not retained as a
parallel product contract. The later-version `default_quote_policy` preference
is stored only as forward preparation and is not applied to 4.4 posting or
delivery.

## Production admission still required

The implementation is ready for acceptance, but the following gates require
production infrastructure, another live implementation, or human evidence that
this checkout cannot manufacture:

- rehearse the phased migration on production-volume data, including backup and
  restore, locks/table rewrites, replica lag, disk headroom, rolling old/new
  writers, and the explicit destructive-contract fence;
- run public/authenticated/admin response differentials against an official
  Mastodon 4.4.22 Rails deployment and exercise FEP-044f, RFC 9421, legacy
  signatures, collections, and remote reply fetching with live remote servers;
- exercise desktop/mobile/touch/keyboard/screen-reader/reduced-motion flows,
  mail-client rendering, and retained-theme visual regression with humans and
  real browsers;
- rehearse Redis Sentinel/failover and namespace cutover, web/worker restart,
  partial storage failure with the deployed providers, Meilisearch outage,
  FASP callback/backfill, bulk mail, and self-destruct in the target topology;
- explicitly approve or remediate the residual Debian and frontend dependency
  inventory, then rescan the exact promoted image if any package or base layer
  changes.

The repository default Mastodon version must be changed to `4.4.22` only after
these acceptance items pass. Until then, code compatibility and production
release admission are deliberately reported separately.
