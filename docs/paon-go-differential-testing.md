# Rails/Go differential testing

The release comparison uses manifests generated by each real router and sends the same declared cases to separately running Rails and Go processes. It does not derive expected responses from Rails specs.

```sh
task routes:audit

PAON_RAILS_REFERENCE_URL=http://127.0.0.1:3001 \
PAON_GO_REFERENCE_URL=http://127.0.0.1:3000 \
task test:differential
```

`routes:audit` fails when a Rails route has no Go route or recorded accepted non-route. The only built-in accepted non-routes are the disabled Mastodon crypto controllers listed by `docs/tasks/07-reviewed-no-action.md`.

Cases live in `testdata/differential/core.json`. Each case has a stable contract ID, method, path, request headers/body, and the exact response headers to compare. Status and body are always compared. JSON is compared structurally; HTML and other bodies are compared byte-for-byte after normalizing only the two configured base URLs. Redirects are not followed. Generated values may be replaced by explicit JSON Pointer entries, and volatile headers must be named explicitly.

The Rails and Go databases must be seeded from the same fixture and use controlled clocks before running stateful cases. A missing reference URL, missing route manifest, request failure, undeclared header difference, or body difference is a failure rather than a skipped test.
