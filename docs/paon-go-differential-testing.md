# Rails/Go differential testing

The release comparison uses manifests generated by each real router and sends the same declared cases to separately running Rails and Go processes. It does not derive expected responses from Rails specs.

```sh
PAON_RAILS_ROUTE_MANIFEST=tmp/rails-routes-4.5.15.json task routes:audit

PAON_RAILS_REFERENCE_URL=http://127.0.0.1:3001 \
PAON_GO_REFERENCE_URL=http://127.0.0.1:3000 \
task test:differential
```

Use `task test:differential:core` while bringing up the two reference processes. The release command `task test:differential` additionally runs `testdata/differential/authenticated.json` and intentionally fails unless the deterministic fixture exports the following values to both processes:

- authorization headers: `PAON_DIFF_USER_AUTHORIZATION`, `PAON_DIFF_OWNER_AUTHORIZATION`, `PAON_DIFF_ADMIN_AUTHORIZATION`, and a token without `read:accounts` in `PAON_DIFF_NO_READ_ACCOUNTS_AUTHORIZATION`;
- account IDs: `PAON_DIFF_LOCAL_ACCOUNT_ID`, `PAON_DIFF_REMOTE_ACCOUNT_ID`, and `PAON_DIFF_SUSPENDED_ACCOUNT_ID`;
- status IDs: `PAON_DIFF_PUBLIC_STATUS_ID`, `PAON_DIFF_PRIVATE_STATUS_ID`, and `PAON_DIFF_BLOCKED_STATUS_ID`;
- URL-encoded fixture values: `PAON_DIFF_SEARCH_QUERY`, `PAON_DIFF_SEARCH_MAX_ID`, and `PAON_DIFF_LINK_URL_QUERY`.
- 4.5 ActivityPub fixtures: `PAON_DIFF_CONTEXT_ID` (`accountID-statusID`), `PAON_DIFF_NUMERIC_ACCOUNT_ID`, `PAON_DIFF_NUMERIC_STATUS_ID`, and `PAON_DIFF_ACCEPTED_QUOTE_ID`;
- official Quote fixtures: `PAON_DIFF_QUOTED_STATUS_ID`, `PAON_DIFF_ACCEPTED_QUOTE_STATUS_ID`, `PAON_DIFF_QUOTE_POLICY_STATUS_ID`, and `PAON_DIFF_QUOTE_TARGET_STATUS_ID`;
- feed and username fixtures: URL-encoded `PAON_DIFF_TOPIC_TAG` and a unique ASCII `PAON_DIFF_USERNAME_BLOCK` value;
- target-specific browser credentials: Rails and Go user/admin `Cookie` header values and CSRF tokens in `PAON_DIFF_RAILS_USER_COOKIE`, `PAON_DIFF_RAILS_USER_CSRF_TOKEN`, `PAON_DIFF_GO_USER_COOKIE`, `PAON_DIFF_GO_USER_CSRF_TOKEN`, `PAON_DIFF_RAILS_ADMIN_COOKIE`, `PAON_DIFF_RAILS_ADMIN_CSRF_TOKEN`, `PAON_DIFF_GO_ADMIN_COOKIE`, and `PAON_DIFF_GO_ADMIN_CSRF_TOKEN`.

Authorization values are read from the environment at request time and are never written to the manifest or result JSON. `rails_headers_from_env` and `go_headers_from_env` allow the same browser mutation to use each server's own session and CSRF credentials without weakening response comparison or exposing those credentials. Common request headers remain in `headers`/`headers_from_env`; target-specific headers override a common header only for that target. `${NAME}` references in paths, bodies, and literal header values are also strict: an absent value fails the case instead of silently testing a different route.

`routes:audit` fails when a Mastodon 4.5.15 Rails route has no matching Go route. It has no built-in controller exclusions; removed routes must be absent from the reference manifest rather than accepted as Paon exceptions. `PAON_RAILS_ROUTE_MANIFEST` defaults to `tmp/rails-routes-4.5.15.json`.

Cases live in `testdata/differential/core.json` and `testdata/differential/authenticated.json`. Each case has a stable contract ID, method, path, request headers/body, and the exact response headers to compare. The core manifest covers health, XRD/JRD discovery, OAuth metadata, NodeInfo, instance v1/v2, empty batch reads, authentication boundaries, and OAuth revoke preflight. The seeded manifest covers local/remote/suspended accounts, public/private/blocked statuses, user/owner/admin/scope boundaries, locale-sensitive non-disclosure, pagination, grouped notifications, policy/requests, annual reports, search, link timelines, official Quote create/list/revoke and interaction policy, QuoteAuthorization, FEP-7888 context collections/pages, numeric ActivityPub actor/outbox/followers/status routes, the four feed-access settings and `view_feeds` override, username blocks, and Posting defaults including private-to-`nobody` quote-policy coercion. Status and body are compared by default. JSON is compared structurally; HTML and other bodies are compared byte-for-byte after normalizing only the two configured base URLs. Redirects are not followed. Generated values may be replaced by explicit JSON Pointer entries, and volatile headers must be named explicitly. When a case does not declare a narrower header set, the harness also compares CORS allow/expose/credential/max-age headers in addition to content, cache, pagination, redirect, authentication, and rate-limit headers.

`AUTH-SIGNIN-001` intentionally sets `compare_body: false`: Paon retains and extends its existing localized sign-in design instead of importing the Mastodon 4.5 UI. The admin discovery/username-block and Posting-defaults web cases use the same narrow exception because Paon extends its retained UI instead of copying upstream HTML. Those cases still require the exact status and declared HTTP headers; their markup, form parsing, authorization, CSRF, and localized behavior are covered by focused Paon API/UI tests. No REST or ActivityPub case may opt out of structural body equality. Instance thumbnail and icon source pointers are normalized for the same retained-UI reason, while their JSON structure, sizes, and all non-UI fields remain exact.

Status quotes use Mastodon 4.5's official PostgreSQL, REST, notification, and
FEP-044f contracts. Status and scheduled-status creation accept
`quoted_status_id`; posting defaults and status creation accept the official
quote policy values; REST status entities expose the official full or shallow
quote and quote-approval shapes; and QuoteRequest, Accept, Reject,
QuoteAuthorization, revoke, delete, and update activities use the upstream
ActivityPub vocabulary and lifecycle. Quoting a boost resolves its proper
original status before visibility and policy checks. Quote responses and
activities require structural equality without Go-only JSON exceptions.

The retired Paon/DynamoDB fields `quote_id` and `quote_original_url` are not
accepted or serialized. Legacy DynamoDB data is available only to
`paon-admin quotes cutover`; the normal web, worker, REST, serializer,
ActivityPub, streaming, notification, and search paths read and write only the
official PostgreSQL model and never dual-write.

Rails and Go must use isolated copies of the same resettable fixture and controlled clocks before running stateful cases. The fixture must include an accepted official quote, a separately owned quotable status, a mutable local status, a local numeric-ID actor/status, a local FEP-7888 conversation, local/remote public-feed and tagged statuses, and matching user/admin roles and sessions. The authenticated manifest is intentionally ordered: it reads the accepted quote before revoking it, changes discovery settings before checking feed gates, changes Posting defaults before creating a defaulted post, and creates the username block before reading the index. Reset both fixture copies and Redis idempotency keys before every complete run; do not run stateful cases concurrently or against one shared database. A missing reference URL, missing route manifest, request failure, undeclared header difference, or body difference is a failure rather than a skipped test.
