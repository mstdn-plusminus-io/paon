# Rails/Go differential testing

The release comparison uses manifests generated by each real router and sends the same declared cases to separately running Rails and Go processes. It does not derive expected responses from Rails specs.

```sh
PAON_RAILS_ROUTE_MANIFEST=tmp/rails-routes-4.3.23.json task routes:audit

PAON_RAILS_REFERENCE_URL=http://127.0.0.1:3001 \
PAON_GO_REFERENCE_URL=http://127.0.0.1:3000 \
task test:differential
```

Use `task test:differential:core` while bringing up the two reference processes. The release command `task test:differential` additionally runs `testdata/differential/authenticated.json` and intentionally fails unless the deterministic fixture exports the following values to both processes:

- authorization headers: `PAON_DIFF_USER_AUTHORIZATION`, `PAON_DIFF_OWNER_AUTHORIZATION`, `PAON_DIFF_ADMIN_AUTHORIZATION`, and a token without `read:accounts` in `PAON_DIFF_NO_READ_ACCOUNTS_AUTHORIZATION`;
- account IDs: `PAON_DIFF_LOCAL_ACCOUNT_ID`, `PAON_DIFF_REMOTE_ACCOUNT_ID`, and `PAON_DIFF_SUSPENDED_ACCOUNT_ID`;
- status IDs: `PAON_DIFF_PUBLIC_STATUS_ID`, `PAON_DIFF_PRIVATE_STATUS_ID`, and `PAON_DIFF_BLOCKED_STATUS_ID`;
- URL-encoded fixture values: `PAON_DIFF_SEARCH_QUERY`, `PAON_DIFF_SEARCH_MAX_ID`, and `PAON_DIFF_LINK_URL_QUERY`.

Authorization values are read from the environment at request time and are never written to the manifest or result JSON. `${NAME}` references in paths, bodies, and literal header values are also strict: an absent value fails the case instead of silently testing a different route.

`routes:audit` fails when a Mastodon 4.3.23 Rails route has no matching Go route. It has no built-in controller exclusions; the E2EE/crypto routes removed in Mastodon 4.3 must be absent from the reference manifest rather than accepted as Paon exceptions. `PAON_RAILS_ROUTE_MANIFEST` defaults to `tmp/rails-routes-4.3.23.json`.

Cases live in `testdata/differential/core.json` and `testdata/differential/authenticated.json`. Each case has a stable contract ID, method, path, request headers/body, and the exact response headers to compare. The core manifest covers health, XRD/JRD discovery, OAuth metadata, NodeInfo, instance v1/v2, empty batch reads, authentication boundaries, and OAuth revoke preflight. The seeded manifest covers local/remote/suspended accounts, public/private/blocked statuses, user/owner/admin/scope boundaries, locale-sensitive non-disclosure, pagination, grouped notifications, policy/requests, annual reports, search, and link timelines. Status and body are compared by default. JSON is compared structurally; HTML and other bodies are compared byte-for-byte after normalizing only the two configured base URLs. Redirects are not followed. Generated values may be replaced by explicit JSON Pointer entries, and volatile headers must be named explicitly. When a case does not declare a narrower header set, the harness also compares CORS allow/expose/credential/max-age headers in addition to content, cache, pagination, redirect, authentication, and rate-limit headers.

`AUTH-SIGNIN-001` intentionally sets `compare_body: false`: Paon retains and extends its existing localized sign-in design instead of importing the Mastodon 4.3 UI. That case still requires the exact status and declared HTTP headers; Paon's sign-in markup and behavior are covered by the API web/session and frontend tests. Instance thumbnail and icon source pointers are normalized for the same reason, while their JSON structure, sizes, and all non-UI fields remain exact.

Paon's status quote fields remain a deliberate API extension: an unquoted status includes `quote_id: null` and `quote_original_url: null`, while Mastodon 4.3.23 omits those keys. The seeded public, private-owner, blocked, batch, pinned, and grouped-notification response cases declare only those exact locations through `go_only_json_pointers`. A `*` segment matches array entries. The harness removes a declared field only from the Go response, requires that it is present there, and fails if Rails starts returning the same field. All surrounding status fields and nested structures therefore remain exact comparisons.

The Rails and Go databases must be seeded from the same fixture and use controlled clocks before running stateful cases. A missing reference URL, missing route manifest, request failure, undeclared header difference, or body difference is a failure rather than a skipped test.
